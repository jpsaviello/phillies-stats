# Backend API Proxy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** All external API calls go through a backend service (`server/`) so the Odds API key lives server-side only, enabling public deployment.

**Architecture:** Hono + `@hono/node-server` app in `server/` (own package.json, no workspace). Routes: `/api/health`, `/api/mlb/*` (allowlisted passthrough to statsapi.mlb.com/api/v1), `/api/odds` (key + 30-min in-memory cache). Client `BASE` → `/api/mlb`; Vite dev/preview proxy `/api` → :8080. Second Docker image `phillies-stats-api:latest`; k8s Deployment + ClusterIP Service; ingress `/api` path; key via imperative Secret `phillies-stats-odds`.

**Tech stack:** Hono, tsx, TypeScript; existing React/Vite frontend; kustomize k8s manifests.

## Global Constraints

- The Odds API key must never appear in the client bundle, any `VITE_*` var, or a committed file.
- MLB passthrough is GET-only with a path-prefix allowlist (`/teams/`, `/stats`, `/standings`, `/schedule`, `/people/`) — not an open relay.
- Odds failures stay fail-soft end to end (503 keyless → client `.catch(() => [])`).
- No CORS middleware (same-origin via Vite proxy / ingress).
