# OPS Trend Pill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Batters in the game log modal get a third trend pill, **OPS**, plotting season-to-date OPS over the season next to Rolling AVG and HR Pace. Pitchers and the last-10 table are untouched.

**Architecture:** The gameLog endpoint's per-game `stat.ops` is already season-to-date (verified live against the official cumulative formula, 2026-07-14). So: add `ops: string` to `BattingGameStat`, add an `opsProgression` helper to `src/utils/trends.ts` that parses it (skipping the first 9 games and any non-finite parse), and append one entry to `TREND_STATS.hitting` in `GameLogModal`. No fetch, chart, or table changes.

**Tech Stack:** React 19, TypeScript, Vite, Tailwind v4, MLB Stats API — no new dependencies, no test runner; verify via webapp-testing.

## Global Constraints

- Plot the API's `ops` string directly — do **not** recompute OPS from counting stats (see spec's rejected alternative)
- First point at game 10 (`minGames = 10`), matching where Rolling AVG starts; skip non-finite parses — never emit `NaN`
- OPS formatting: three decimals, leading zero stripped below 1 (`.912`), kept at/above 1 (`1.024`)
- Pitching pills unchanged; default hitting selection stays Rolling AVG
- Fewer than 2 points → existing "Not enough games yet" placeholder
